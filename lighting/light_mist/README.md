# Light mist

A very thin, light-reactive atmosphere across the level, separate from kill-boundary modes and sepia grading. The trial is disabled by default, including on Level 1, after a reported frame-rate drop with little visible benefit. **IndoorLighting → Light Mist Enabled** remains available for controlled comparisons. Other indoor levels also keep the effect off until explicitly enabled.

The authored `LightMist` child is a native `FogVolume` with world shape. Its shader samples two scales of smooth, world-space 3D noise, including height, and slowly drifts that density field. Density varies gently around 0.004 rather than forming opaque cloud patches. Existing light colours and light energies supply the illumination; there is no fog emission, ambient injection, or additional light.

Tune the shared `light_mist_settings.tres` resource through the component's Settings property. While testing, edit the running component's Settings in the **Remote** Inspector: changes now refresh its uniforms and environment immediately. Editing the Local Inspector or resource file belongs to the editor process and still requires restarting the level. Density controls visibility, Noise Strength controls variation, Noise Scale controls the size of the variations, and Drift Velocity controls their slow movement. The native fog computation range is 32 metres; moderate temporal blending limits trails from the moving headlamp. A zero temporal blend disables reprojection. Scene pause freezes noise drift.

Enabling the feature duplicates the rig's current Environment for that instance, preserving its exposure, glow and other authored properties. The uniform fog density is zero, so the noisy volume supplies all the density. Disabling the toggle or removing the component restores the original Environment, while preserving an external replacement if another system has taken ownership.

The effect uses [Godot's native volumetric fog](https://docs.godotengine.org/en/stable/tutorials/3d/volumetric_fog.html), which requires Forward+. This project already selects Forward+. Camera environments that override the rig's WorldEnvironment need volumetric fog enabled independently.

The normal follow-camera comparison showed mostly a warm haze rather than distinct light shafts. A local Godot 4.7.2 / Metal comparison on an Apple M2 Pro, with paused Level 1 and 15 lights at a 3840×2160 viewport measured median frame intervals of about 16.0 ms with the effect off and 17.0–17.2 ms with it on; uniform density and the custom noise had similar timings. This was a local static-scene comparison, not a reproduction of the reported large drop during gameplay. The Metal backend returned zero for GPU timing queries, so these are wall-clock frame intervals, not GPU measurements. The trial stays off by default; increasing density is not a proven fix for either visibility or performance.
